Trained LightGBM regression models + Random Forest fertility classifier for the SoilMap prediction API (`POST /api/predict/`).

## Setup — extract models before running the server

```bash
cd agri_ai/soil/models/
unzip -o models.zip
```

That's it. The server loads all `.pkl` files at startup from this directory (see `agri_ai/soil/__init__.py`).

---

## Inference pipeline

Predictions run in dependency order (each target feeds into the next as a cross-feature):

```
ph → ec → organic_carbon → n → p → k → s → fe → zn → cu → b → mn
```

Environmental inputs fetched automatically per request:
- **Weather** — temperature (°C) + rainfall (mm) via Open-Meteo API
- **NDVI** — vegetation index via Google Earth Engine (falls back to 0.55 if GEE not authenticated)
- **Elevation** — via GEE (falls back to 200 m)
- **Soil texture** — clay/sand/silt % via SoilGrids REST API

If GEE is not configured, the pipeline uses sensible defaults and still returns valid predictions.

## GEE setup (optional — improves NDVI + elevation accuracy)

```bash
pip install earthengine-api
earthengine authenticate
```

Then set your GEE project in `ml_pipeline/ndvi.py` and `ml_pipeline/add_elevation_to_dataset.py`.

## Retraining

The retrain endpoint is available at `POST /api/retrain/` (admin only).  
New sensor data uploaded via `POST /api/soil-map/upload/<device_id>/` is automatically stored in `DeviseApisFields` and can be used to retrain.

To retrain manually:
```bash
cd agri_ai/soil/training/
python retrain.py
```

New `.pkl` files are written to `agri_ai/soil/models/` and hot-reloaded by the running server.

---

## Training data (optional — only needed to retrain)

Retraining reads from `agri_ai/soil/data/`, which is not committed to git and must be placed manually:

```
agri_ai/soil/data/raw/soilcard/      # raw Soil Health Card source data
agri_ai/soil/data/processed/         # cleaned dataset (final_cleaned_dataset.csv), generated by preprocessing.py
```

This data is available as `data.zip` in the `ai_ml_data_agriculture` GitLab repo (branch `soil_data`) alongside `models.zip`. It is **not required** for the live `POST /api/predict/` endpoint — only for running `preprocessing.py` / `retrain.py` again.
